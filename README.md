About Me

I'm a Systems Engineer and Full Stack Developer focused on enterprise software: ERPs, internal tools, APIs, and the automations businesses actually run on. I care more about understanding why a feature is needed than about writing code fast. Before touching a framework, I look at the business process behind it — what's manual, what breaks, what should talk to what.

Lately I've been going deeper into software architecture, application security, and building systems that can scale without falling apart. Alongside that, I'm also building my own software studio, aimed at bringing this kind of engineering to small and medium businesses still running on spreadsheets and manual processes.

<br/>
How I Think About Software
<div align="center">

Understand the problem → Design the system → Build the solution.

</div>

I don't start with code. I start by mapping out the business process — who does what, where the friction is, what's currently manual. Only after that do I think about stack, structure, and implementation.

A few things that guide how I work:

I ask why a feature is needed before I build it, not just what it should do.
I look for manual processes that can become digital systems.
I care about structure and maintainability more than shipping something that merely works.
Frontend, backend, database, and infrastructure should behave like one coherent system, not four disconnected parts.
I'd rather design something that's easy to extend in a year than something that's fast to write today.
